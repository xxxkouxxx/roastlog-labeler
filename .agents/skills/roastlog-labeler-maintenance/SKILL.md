# RoastLog ラベル管理・印刷

対象はこのリポジトリの静的アプリ `index.html`。プロジェクトルートの `AGENTS.md` と `NEXT_SESSION.md` を先に読む。CURRENT_STATE／AI運用HUBがある場合は、その承認範囲も確認する。存在しなければ推測で承認を補わない。

## データと操作の境界

- 私用の豆はブラウザの `roastlog_beans`。公開用のスナップショットは `labels.json`。ローカル下書きは `roastlog_public_labels_draft`。この3つを混同しない。
- 公開ラベルの閲覧は `viewingPublicLabelBean` に保持する。`beans` に追加してはならない。表示・PNG・QR・デザイン変更は `getCurrentBean()` で同じレコードを使う。
- 公開レコードのQR URLは既存の `labelId` を保持する。Beanから生成するIDで再ハッシュしない。
- JSONの書き出しや `status: published` は配信完了の証拠にならない。「読込ファイル」「下書き」「公開サイトで確認済み」を区別する。
- 焙煎日が空のテンプレートは印刷可能だが、公開用JSONには書き出さない。`originNote` を全変換経路で保持し、`ORIGIN_STORIES` に産地の事実を創作しない。
- `labels.json`、テンプレート、生豆データはUI改修だけで変更しない。実データを使う書き出し・置換は依頼範囲を確認する。
- staging・commit・push・公開・実機印刷は個別の承認対象。スキルの使用やUIテストを承認の代わりにしない。

## UIとプレビュー

- 2Dは印刷内容の確認用。3Dは豆袋への配置イメージで、実際の袋寸法や印刷品質を保証しない。
- Three.jsはバージョン固定のimport mapから3D選択時だけ読み込む。読込失敗／WebGL不可では2Dへ戻し、PNG・公開用JSONを使える状態にする。
- 3DテクスチャとPNGは共通の `renderLabelCanvas()` を使う。選択やサイズの連続変更で古い非同期結果が新しい表示を上書きしないようにする。
- 常時回転を前提にしない。操作・サイズ変更時に描画し、不要なテクスチャ・geometryと終了時のGPUリソースを解放する。
- 表ラベル・QR付きはサイズ選択可能。裏ラベルは62×90mm、シンプル裏は62×62mm固定。画面のサイズ説明、PNGのpx寸法、印刷用mm寸法を揃える。
- 印刷対象の祖先に `display: none` を適用しない。3D表示中でも印刷対象は2Dラベル。管理UIや3Dの豆袋を印刷しない。

## 検証

`node scripts/test_labeler.js` でID、スナップショット、検索・絞り込み、サイズ、PNGと印刷設定の回帰を確認する。これは印刷機やブラウザの描画を代替しない。

ローカルHTTPサーバをループバックで起動し、利用可能なBrowserスキルで実画面を検証する。既存の実運用ブラウザデータを書き換えず、テスト用のlocalhostで実施する。

- PC／スマホ幅：検索、キーボード選択、固定ナビ、ラベルの欠け・横はみ出し。
- 4テーマ／3サイズ：固定サイズ、公開ラベル選択時の追従、2D⇔3D、回転・角度リセット。
- PNG：実ファイルを取得し、300dpi換算のpx寸法と内容を確認。
- QR：`#label-<labelId>` の実ファイル由来レコード、編集UI非表示、未知IDの案内。
- JSON：焙煎日なし／公開レコードのガードと、書き出しだけでは公開完了にならない表示。
- 3D不可：2Dフォールバックと通常操作の継続。実施できなければ未検証と明記する。

実機印刷、iPhone実機、公開サイト反映は別の確認。未実施をPASSにしない。結果は Result / Changes / Verification / Open Items / NEXT で簡潔に報告する。
